# Git提交管理铁律

> 🚨 这是项目管理的核心铁律，所有团队成员必须无条件遵守
>
> **违反后果：** 立即纠正 + 记录在案 + 影响绩效评估

## 📋 高频提交铁律

### **⏰ 提交频率要求**
- **每15分钟：** 检查是否有可提交变更
- **每完成一个函数：** 立即提交
- **每修复一个bug：** 立即提交
- **每完成一个组件：** 立即提交
- **每完成一个API：** 立即提交
- **每完成一个测试：** 立即提交

### **📝 提交信息规范**
遵循Conventional Commits规范：
```
<type>(<scope>): <subject>

<body>

<footer>
```

**类型说明：**
- `feat:` - 新功能
- `fix:` - 修复bug
- `docs:` - 文档更新
- `style:` - 代码格式
- `refactor:` - 代码重构
- `test:` - 测试相关
- `chore:` - 构建/工具

## 🔒 强制监督机制

### **监督责任分工：**
- **项目助理（我）：** 每15分钟检查Git状态
- **前端工程师：** 前端代码提交监督
- **后端工程师：** 后端代码提交监督
- **测试专家：** 测试代码提交监督

### **违规处理流程：**
1. **立即发现** - 15分钟检查时发现
2. **立即纠正** - 强制要求立即提交
3. **立即记录** - 记录在EXECUTION_LOG.md
4. **立即汇报** - 向您汇报违规情况

## 📊 提交质量检查清单

### **每次提交前必须检查：**
- [ ] 代码是否可编译/可运行
- [ ] 是否有明确的提交信息
- [ ] 是否遵循了类型规范
- [ ] 是否更新了相关文档
- [ ] 是否通过了基础测试

### **文档更新要求：**
- **TODOS.md** - 任务状态变更立即更新
- **EXECUTION_LOG.md** - 每30分钟更新进度
- **技术文档** - 功能完成立即更新

## 🚨 违规记录模板

```
### [时间] - Git提交违规
- **违规类型：** [未提交/提交信息不规范/未更新文档]
- **违规人员：** [前端/后端/测试/项目助理]
- **违规原因：** [具体原因]
- **纠正措施：** [立即执行的纠正行动]
- **预防措施：** [避免再次发生的措施]
```
